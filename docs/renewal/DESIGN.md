# 確認画面の DESIGN.md(リニューアル案)

ディレクター1人が、1案件 1,000〜10,000 ページを1ページずつ目視で確認し、FTP に上げる前の HTML を確定する画面の視覚規則である。
画面を作る前にこの規則を決め、作ったあとはこの規則に合っているかで見直す。
見た目の質は、Awwwards に選ばれる水準を目標にする(2026-10-05 ユーザー)。
ただし、速さ、AA のコントラスト、キーボードだけでの操作は、見た目のために下げない。

## コンセプト「校正台」

自治体の文書を1枚ずつ校正し、判を押して次へ回す。
この業務そのものを、画面の言葉にする。

- 地は温かい紙の色で、ごく薄い紙の目を重ねる。確認するページは、中央に置いた1枚の紙として見せる。
- 削除は朱の赤字、追加は藍の青字。候補は、紙の余白に書いた番号付きの「指示」として見せ、右の列の指示と番号でつなぐ。
- 確定は、朱の丸い判を押す動作にする。後回しは付箋、確定済みは「済」の判で示す。
- 道具らしさは、罫線の整い方、数字の揃え方、余白の比率で出す。飾りの絵や写真は使わない。

## 利用の前提

- 使うのはディレクターだけ。1日5時間、1ページ平均およそ2分で流す(10,000 ページを60営業日で終える場合)。
- 一括処理がページごとに候補を作り、目視の深さを3段階に分けてある。段階0は開かない、段階1は差分を見て採用する、段階2は読んで判断する。
- 主な操作はキーボードで行う。マウスでもすべて操作できる。

## 骨格

- 上端に案件の帯、その下に3つの列(左が待ち行列、中央が紙、右が校正の指示)、下端に確定の帯。画面全体はスクロールさせず、各列が自分の中でスクロールする。
- 案件の帯は、案件名(明朝の大きな文字)と、進み具合の帯(確定、段階2の残り、段階1の残り、段階0 を1本の帯の区切りで示す)と、大きな数字の「確定 / 移行する」で作る。
- 中央の紙は最大 760px の幅で、列の中央に置く。紙の左の余白(56px)に、候補の番号の指示を置く。
- 浮いて重なるパネルは使わない。確認や入力は確定の帯の中で行う。ダイアログはキーの一覧と、案件で採用中のルールだけ。
- 1280×800 で3列が収まること。1100px 未満では校正の指示の列を紙の下に回す。

## 色

色は意味にだけ使う。

| 名前 | 値 | 役割 |
| --- | --- | --- |
| 地 | `#efe9dd` | 画面の地。紙の目を重ねる |
| 紙 | `#fbf8f1` | 列と、中央の紙の面 |
| 墨 | `#1d1a16` | 文字。選択の左枠(3px) |
| 薄墨 | `#5b5346` | 補助の文字 |
| 罫 | `#d8cfbd` | 面を区切る線 |
| 枠 | `#8f8574` | 操作できる部品の枠(紙に対して 3:1 以上) |
| 朱 | `#b3311f`、地 `#fbe9e4` | 削除(赤字)、確定の判、「済」の判 |
| 藍 | `#1f4a86`、地 `#e6edf8` | 追加(青字)、フォーカスの枠、リンク、主ボタン |
| 芥子 | `#7a5300`、地 `#f8eccb` | 要確認、後回しの付箋 |
| 紫 | `#5a3d8a`、地 `#efe9f6` | 構造のタグの札(`<h2>` `<table>` など) |
| 蛍光 | `#fff1a8` | 選択中の指示の箇所に引く蛍光ペン(文字の背景だけ) |

- 選択は「墨の左枠」と「紙が一段手前に出る影」で示す。色の面で塗らない。蛍光は、紙の上の選択中の箇所にだけ引く。
- 朱は「削除」と「確定」の両方に使う。どちらも校正で朱を入れる行為なので、意味は一つ(朱を入れる)とみなす。
- 決定の状態(採用、却下、編集して採用、後回し、案件で採用)は、色に加えて文字と記号で示す。色だけに頼らない。
- 文字と背景のコントラストは 4.5:1 以上。操作できる部品の枠は 3:1 以上。面を区切るだけの罫は、この限りでない。

## 書体

| 用途 | 書体 |
| --- | --- |
| 案件名、ページ題名、列の見出し、大きな数字 | `"Shippori Mincho B1", "Yu Mincho", serif` |
| 画面の文字、ボタン、紙の本文 | `"Zen Kaku Gothic New", "BIZ UDPGothic", "Yu Gothic UI", sans-serif` |
| HTML、タグの札、移行管理 ID、キー | `"JetBrains Mono", "BIZ UDGothic", Consolas, monospace` |

- Google Fonts から読み込む。読み込めないときは右の代わりの書体で崩れないこと。
- 大きさは 12px(補助)、14px(画面の文字)、15px(紙の本文)、18px(列の見出し)、24px(ページ題名)、32px(案件名と大きな数字)。
- 数字は等幅の数字(`font-variant-numeric: tabular-nums`)で揃える。

## 形と奥行き

- 角丸は、紙と列が 6px、ボタンと札が 4px、判は丸。
- 影は2段だけ。紙の面(`0 1px 0 rgba(29,26,22,.04), 0 18px 40px -24px rgba(29,26,22,.28)`)と、選択して手前に出た指示(`0 8px 20px -12px rgba(29,26,22,.35)`)。
- 余白は 4px の倍数。紙の内側は 48px。
- 地には紙の目(SVG のノイズ、不透明度 6% 以下)を重ねる。文字の読みやすさに響かない濃さにする。

## 動き

動きは、状態が変わったことを伝えるときだけ使う。

| 場面 | 動き | 長さ |
| --- | --- | --- |
| ページを確定する | 紙に朱の判が落ちる(大きく傾いて現れ、縮んで定まる)。紙が左へ抜け、次の紙が右から差し込まれる | 判 320ms、差し替え 280ms |
| 候補を選ぶ | 紙の上の該当箇所に、蛍光ペンが左から右へ引かれる | 220ms |
| 候補を判断する | 指示の印(✓、✕、△)が小さく弾む | 160ms |
| 進み具合 | 帯が伸びる | 400ms |

- 曲線は `cubic-bezier(.2,.8,.2,1)`。
- `prefers-reduced-motion: reduce` では、すべての動きを止め、状態だけを切り替える。
- 背景の飾りの動き、ホバーで浮き沈みするボタン、無意味な読み込みの演出は使わない。

## 部品

- **待ち行列の行**: 移行管理 ID(等幅)、ページ題名、段階と難易度。高さは 80px に固定する(本実装の仮想スクロールのため)。確定済みは右端に朱の「済」の小さな判、後回しは芥子の付箋の角。
- **段階の印**: 段階0〜2 を、点の数(○、●、●●)と文字(自動、一目、読む)で示す。段階2は太字。
- **紙の上の指示**: 左の余白に、候補の番号を丸で囲んだ指示を置き、タグの札とルールの名前を添える(番号だけでなく名前で照合する)。修正前は朱の取り消し線、修正後は藍の下線。判断したあとは、修正前を畳んで残す。
- **校正の指示のカード**: 番号、タグの札、ルールの名前、状態、修正前と修正後の短い抜き出し。選択中のカードだけが手前に出て、根拠と操作を見せる。操作はカードの末尾に固定する。
- **確定の判**: 確定の帯の右端に、朱の丸い判のボタン(直径 56px、「確定」の文字)。押せないときは、判を薄墨の線だけにし、理由を帯に書く。
- **キー**: キーは小さな鍵盤の形(下に 2px の厚み)で示す。読み上げには含めない(`aria-hidden`)、ボタンには `aria-keyshortcuts` を付ける。

## キーボード

| キー | 動き |
| --- | --- |
| J / K | 次の候補 / 前の候補 |
| A | 採用 |
| R | 却下 |
| E | 編集して採用(Ctrl+Enter で決定、Esc で取り消し) |
| L | 後回し(質問の下書きを1行書ける。Enter で決定、Esc で書かずに後回し) |
| Shift+A | このルールを案件の全ページで採用(確定の帯で確かめてから適用。CapsLock の A では動かない) |
| Enter | このページを確定して次のページへ |
| Shift+Enter | 残りの候補をすべて採用して確定(要確認の候補が残るページでは使えない) |
| N / P | 次のページ / 前のページ(確定しない) |
| V | 見た目の差分と HTML の差分を切り替え |
| ? | キーの一覧 |

- 決定は何度でも押し直せる。確定したページも、確定の帯の「確定を取り消す」で戻せる。
- スクリーンリーダーのブラウズモードでは単一文字のキーが移動キーとぶつかるので、本実装では設定で「修飾キーを要求する」を選べるようにする。
- 操作のあとに画面を描き直しても、フォーカスは選択中の候補に戻す。

## 実装へ持ち越すこと

- 紙の中身(旧サイト由来の HTML)は、サニタイズするか sandbox の iframe で描く。紙の見出しを画面の見出しの階層に混ぜない。
- 差分は、段落単位では修正前と修正後を積む。語単位の差分(段階1の短い修正)を行内で見せる形は、本実装で比べて決める。
- 待ち行列は仮想スクロールにし、状態が変わった行だけを描き直す。
- 判断は操作のたびに保存する(途中で閉じる前提)。

## してはいけないこと

- 色を新しい役割に足す。足したくなったら、文字か記号で表せないかを先に考える。
- 浮いて重なるパネル、背景の飾りの動き、ホバーで浮き沈みするボタン。
- 開発者向けの表示(ルールの ID、ファイル名、内部の状態)を、既定の画面に出す。
- 見た目のために、コントラスト、フォーカスの見え方、キーボードでの操作を下げる。
