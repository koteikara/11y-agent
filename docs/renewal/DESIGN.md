# 確認画面の DESIGN.md(リニューアル案)

ディレクター1人が、1案件 1,000〜10,000 ページを1ページずつ目視で確認し、FTP に上げる前の HTML を確定する画面の視覚規則である。
画面を作る前にこの規則を決め、作ったあとはこの規則に合っているかで見直す。
見た目の質は、Awwwards に選ばれる水準を目標にする(2026-10-05 ユーザー)。
ただし、速さ、AA のコントラスト、キーボードだけでの操作は、見た目のために下げない。

## コンセプト「校正台」

自治体の文書を1枚ずつ校正し、決裁欄に判を押して次へ回す。
この業務そのものを、画面の言葉にする。
主役の仕掛けは「机の上の1枚の紙と、その決裁欄に落ちる判」で、レイアウト、色、動き、一覧の印をこれに揃える。

- 中央の列は机。机の上に、確認するページを1枚の紙として置く。紙の右上に点線の丸い「確認印」の欄がある。
- 削除は朱の縦罫と取り消し線(赤字)、追加は藍の縦罫と下線(青字)。紙の上では色の面を塗らない。候補は、紙の左の余白に番号の丸を付けた「指示」として見せ、右の列の指示と番号と名前でつなぐ。
- 確定は、朱の丸い判を押す動作。押すと紙が上端へ戻り、決裁欄に「済」が落ち、紙が抜けて次の紙が差し込まれる。待ち行列の確定済みの印も、同じ形の小さな「済」の判にする。後回しは芥子の付箋。
- 道具らしさは、罫線の整い方、数字の揃え方、余白の比率で出す。飾りの絵や写真は使わない。

## 利用の前提

- 使うのはディレクターだけ。1日5時間、1ページ平均およそ2分で流す(10,000 ページを60営業日で終える場合)。
- 一括処理がページごとに候補を作り、目視の深さを3段階に分けてある。段階0は開かない、段階1は差分を見て採用する、段階2は読んで判断する。
- 主な操作はキーボードで行う。マウスでもすべて操作できる。

## 骨格

- 上端に案件の帯、その下に3つの列(左が待ち行列、中央が机と紙、右が校正の指示)、下端に決裁の帯。画面全体はスクロールさせず、各列が自分の中でスクロールする。列の中のスクロールは、その列だけを動かす(画面全体を動かさない)。
- 案件の帯は、案件名(明朝 32px)、大きな数字の「確定 / 移行する」、進み具合の帯(確定、段階2の残り、段階1の残り、段階0 を1本の帯の区切りで示す)、今日の確定と残りの見込み。
- 中央の紙は最大 760px の幅で、机の中央に置く。紙の左の余白(60px の位置に朱の淡い罫)に、指示の番号の丸を置く。紙の右上(上 24px、右 28px)に決裁欄(直径 92px)。
- 決裁の帯は、左に明朝の大きな数字で「未判断の数 / 指示の数」、続けて一文の案内、右端に判のボタン。
- 浮いて重なるパネルは使わない。確認や入力は決裁の帯の中で行う。ダイアログはキーの一覧と、案件で採用中のルールだけ。
- 1280×800 で3列が収まること。1100px 未満では、待ち行列と机を上に並べ、校正の指示の列をその下に回し、各列に高さを持たせる。決裁の帯は画面の下に固定する。

## 色

色は意味にだけ使う。

| 名前 | 値 | 役割 |
| --- | --- | --- |
| 地(机) | `#efe9dd` | 画面の地と、中央の列の机。紙の目を重ねる |
| 紙 | `#fbf8f1` | 列の面 |
| 紙の段 | `#fffdf8` | 机の上の紙、選択して手前に出た行とカード、入力欄の面。色ではなく「紙が一段手前にある」ことを示す |
| 墨 | `#1d1a16` | 文字。選択の左枠(3px)。採用の主ボタンの塗り |
| 薄墨 | `#5b5346` | 補助の文字、修正前の文字 |
| 罫 | `#d8cfbd` | 面を区切る線 |
| 枠 | `#8f8574` | 操作できる部品の枠、決裁欄の点線(紙に対して 3:1 以上) |
| 朱 | `#b3311f`、淡 `#fbe9e4` | 削除(赤字)、却下の印、確定の判、「済」の判、紙の左の淡い罫 |
| 藍 | `#1f4a86`、淡 `#e6edf8` | 追加(青字)、採用の印、確定済みの案内、フォーカスの枠、リンク、確かめの主ボタン |
| 芥子 | `#7a5300`、淡 `#f8eccb` | 要確認、後回しの付箋と縦罫 |
| 紫 | `#5a3d8a`、淡 `#efe9f6` | 構造のタグの札(`<h2>` `<table>` など)、見出しのレベルの札(H2、H3) |
| 蛍光 | `#fff1a8` | 選択中の指示の名前に引く蛍光ペン(文字の背景だけ) |

紙の中の罫と枠(表の見出しのセル `#f1ebde`、画像の代わりの枠 `#ece5d6` と `#e6dece`、段階2の斜線 `#d0705f`)は、紙の中の描き分けで、意味の色ではない。

- 選択は「墨の左枠」と「紙の段が手前に出る影」で示す。意味の色の面で塗らない。蛍光は、選択中の指示の名前にだけ引く。
- 朱は「朱を入れる」(削除、却下、確定)、藍は「青で直す・通す」(追加、採用)に使う。
- 色の面(淡い色の塗り)は、HTML の差分の表示と、札だけに使う。紙の上の見た目の差分には塗らない。旧サイト由来の文字の色(赤い文字など)が淡い面に載って読みにくくなるのを避けるため。
- 決定の状態(採用、却下、編集して採用、後回し、案件で採用)は、色に加えて文字と記号(✓、✕、△)で示す。色だけに頼らない。
- 文字と背景のコントラストは 4.5:1 以上。操作できる部品の枠は 3:1 以上。面を区切るだけの罫は、この限りでない。

## 書体

| 用途 | 書体 |
| --- | --- |
| 案件名、ページ題名、列の見出し、大きな数字、判 | `"Shippori Mincho B1", "Yu Mincho", serif` |
| 画面の文字、ボタン、紙の本文 | `"Zen Kaku Gothic New", "BIZ UDPGothic", "Yu Gothic UI", sans-serif` |
| HTML、タグの札、移行管理 ID、キー | `"JetBrains Mono", "BIZ UDGothic", Consolas, monospace` |

- Google Fonts から読み込む(本実装では自分のサーバーに置く)。届くまで明朝の大きな文字は出さず、届いたら 120ms で出す(差し替わる揺れを見せない)。届かないときも 1.5 秒で代わりの書体のまま出す。
- 明朝の見出しと数字には `font-feature-settings: "palt"` を入れ、約物と仮名を詰める。
- 数字は等幅の数字(`font-variant-numeric: tabular-nums`)で揃える。
- 大きさは次の段に限る。

| 大きさ | 使う場所 |
| --- | --- |
| 11px | タグの札、移行管理 ID、キー、修正前と修正後の見出し、付箋、決裁欄の文字 |
| 12px | 補助の文字 |
| 13px | 右の列の修正前と修正後の抜き出し(1ページ2分の流れで一番読む文字) |
| 14px | 画面の文字 |
| 15px | 紙の本文 |
| 18px | 列の見出し、紙の中の見出し |
| 24px | ページ題名、今日の数字、ダイアログの見出し |
| 32px | 案件名、大きな数字 |
| 40px | 決裁欄の「済」の判 |

## 形と奥行き

- 角丸は、紙と列が 6px、ボタンと札が 4px、判と決裁欄は丸。
- 影は2段だけ。机の上の紙(`0 0 0 1px rgba(29,26,22,.07), 0 1px 0 rgba(29,26,22,.04), 0 24px 48px -28px rgba(29,26,22,.38)`)と、選択して手前に出た行とカード(`0 8px 20px -12px rgba(29,26,22,.35)`)。
- 余白は 4px の倍数。紙の内側は上 48px、右 52px、下 56px、左 80px(余白の指示のため)。
- 地と机には紙の目(SVG のノイズ、不透明度 8%)を重ねる。列と紙には重ねない。

## 動き

動きは、状態が変わったことを伝えるときだけ使う。

| 場面 | 動き | 長さ |
| --- | --- | --- |
| 判を押す(確定) | 紙が上端へ戻る。決裁欄に「済」が大きく傾いて現れ、縮んで定まる。紙が少し傾きながら左へ抜け、次の紙が右から差し込まれる | 戻り 260ms、判 320ms、差し替え 280ms |
| 判のボタンを押し込む | 6度傾いて少し縮む(押している間だけ) | 120ms |
| 指示を選ぶ | 指示の名前に、蛍光ペンが左から右へ引かれる | 220ms |
| 指示を判断する | 状態の印(✓、✕、△)が小さく弾む | 160ms |
| 進み具合 | 帯が伸びる | 400ms |

- 曲線は `cubic-bezier(.2,.8,.2,1)`。
- `prefers-reduced-motion: reduce` では、すべての動きを止め、状態だけを切り替える。
- 背景の飾りの動き、ポインタを乗せただけで浮き沈みや回転をするボタン、無意味な読み込みの演出は使わない。

## 部品

- **待ち行列の行**: 移行管理 ID(等幅)、ページ題名、段階と難易度(と付箋)の3段。高さは 80px に固定する(本実装の仮想スクロールのため)。確定済みは右端に朱の「済」の小さな判。後回しと質問中は、3段目に芥子の付箋。フォーカスの枠は行の内側に描く(列のスクロールで切れないように)。
- **段階の印**: 段階0〜2 を、点の数(○、●、●●)と文字(自動、一目、読む)で示す。段階2は太字。
- **紙の上の指示**: 左の余白に番号の丸、続けてタグの札とルールの名前と状態。修正前は朱の縦罫と取り消し線、修正後は藍の縦罫と下線。見出しの候補は、内容の先頭に見出しのレベルの札(H4、H3)を付け、レベルが変わったことを文字の大きさに頼らず見せる。判断したあとは、修正前を畳んで残す。
- **校正の指示のカード**: 番号、タグの札、ルールの名前、状態、修正前と修正後の短い抜き出し(13px)。選択中のカードだけが手前に出て、根拠と操作を見せる。操作は2段で、1段目に「採用」(墨の塗り)、「却下」、「編集」。2段目に破線の罫を挟んで、文字だけのボタンで「後回しにする」「このルールを案件の全ページで採用」。
- **段階0のページ**: 紙には「確認は要りません」、右の列には「自動で採用した指示 n 件」を開いた状態で出し、証跡として見せる。
- **決裁欄と判**: 決裁欄は点線の丸に「確認印」。判が落ちたら点線と文字を消す。確定の判のボタンは直径 64px の朱の丸。押せないときは、薄墨の線だけの丸にし、理由を帯に書く。
- **キー**: 小さな鍵盤の形(下に 2px の厚み)で示す。読み上げには含めない(`aria-hidden`)。ボタンには `aria-keyshortcuts` を付ける。
- **空の状態**: 待ち行列が絞り込みで空になったら、「絞り込みを外す」のボタンを添える。

## キーボード

| キー | 動き |
| --- | --- |
| J / K | 次の指示 / 前の指示 |
| A | 採用 |
| R | 却下 |
| E | 編集して採用(Ctrl+Enter で決定、Esc で取り消し) |
| L | 後回し(質問の下書きを1行書ける。Enter で決定、Esc で書かずに後回し) |
| Shift+A | このルールを案件の全ページで採用(決裁の帯で確かめてから適用。CapsLock の A では動かない) |
| Enter | 判を押して確定し、次のページへ。まだ押せないときは、未判断の数を読み上げる |
| Shift+Enter | 残りの指示をすべて採用して確定(要確認が残るページでは使えない) |
| N / P | 次のページ / 前のページ(確定しない) |
| V | 見た目と HTML の表示を切り替え |
| ? | キーの一覧 |

- 決定は何度でも押し直せる。確定したページも、決裁の帯の「確定を取り消す」で戻せる。
- 確かめ中(Shift+A)と下書き中(L)は、Esc 以外のキーを受けない。別の指示に移って誤って後回しにしないため。
- スクリーンリーダーのブラウズモードでは単一文字のキーが移動キーとぶつかるので、本実装では設定で「修飾キーを要求する」を選べるようにする。
- 操作のあとに画面を描き直しても、フォーカスは選択中の指示に戻す。指示の無いページでは、ページ題名に戻す。

## 実装へ持ち越すこと

- 紙の中身(旧サイト由来の HTML)は、サニタイズするか sandbox の iframe で描く。紙の見出しを画面の見出しの階層に混ぜない。
- 旧サイト由来の文字の色(赤い文字など)は検査の対象で、画面の淡い面には載せない。
- 差分は、段落単位では修正前と修正後を積む。語単位の差分(段階1の短い修正)を行内で見せる形は、本実装で比べて決める。
- 待ち行列は仮想スクロールにし、状態が変わった行だけを描き直す。
- 判断は操作のたびに保存する(途中で閉じる前提)。
- 書体は自分のサーバーに置く。

## してはいけないこと

- 色を新しい役割に足す。足したくなったら、文字か記号で表せないかを先に考える。
- 紙の上の見た目の差分に、色の面を塗る。
- 浮いて重なるパネル、背景の飾りの動き、ポインタを乗せただけで動くボタン。
- 開発者向けの表示(ルールの ID、ファイル名、内部の状態)を、既定の画面に出す。
- 見た目のために、コントラスト、フォーカスの見え方、キーボードでの操作を下げる。
