# リニューアルの方針

2026-10-04 に始めた全体リニューアルで、これまでに決めた方針をまとめた。
細かい設計と根拠は、次の3つの文書にある。
この文書は、その入口として、何を目指し、何を選び、何を選ばなかったかを短く書く。

| 文書 | 中身 |
| --- | --- |
| `FLOW.md` | 案件の始まりから移行後のチェックまでの、ディレクターの業務の流れ |
| `ARCHITECTURE.md` | 仕組みの部品、データの形、CMS に渡す HTML の約束、作る順番 |
| `DESIGN.md`、`review-mockup.html` | 確認画面(校正台)の見た目と操作 |

## 目指すこと

いまは、旧サイトのページをそのまま CMS に取り込み、移行業者が CMS の管理画面でアクセシビリティの手直しをしている。
リニューアル後は、取り込む前にディレクターが直しを確定し、直した HTML を CMS に取り込ませる。
手直しの多くが取り込みの前に移るので、取り込み後の移行業者の作業と承認の差し戻しが減る。

目標は2つある。

- ディレクター1人が1日5時間の確認で、1案件 1,000〜10,000 ページを約3か月の期間内に確定できること。
- 取り込んだあとの手直しと差し戻しを減らすこと。これは修正の候補の精度で決まるので、採用率、見逃し、害のある候補、残る指摘、取り込み後の手直しの5つで測る(`ARCHITECTURE.md` の「目標と測り方」)。

リニューアルを始めた動機は、使い勝手、業務の流れの見直し、画面の見た目の3つである(2026-10-04 のユーザーの判断)。
範囲は、アプリだけでなく、共通のルール、証跡と移行管理シート、CMS への取り込みまでの業務全体とする。

## 前提

ユーザーが決めた前提は次のとおり。

- 使うのはディレクターだけで、案件ごとに1人。移行業者と承認者は、この仕組みの画面を開かない。
- 規模は1案件 1,000〜10,000 ページ(「移行する」の数)で、同時に最大6案件。
- 移行管理シートはディレクターが作る。GAS で書き戻してよい。
- すべてのページを目視で確かめる。そのぶん、自動で作る候補の精度を上げる。
- 直した HTML を共有ドライブに置き、ディレクターが FTP に上げ、取込データの移行元 URL を FTP 上の URL に置き換えて、CMS に取り込ませる。
- CMS の開発チームには、この仕組みのための変更を頼めない。
- データベースを持たない。
- Claude Code は、ディレクターの PC で道具を動かす係にする。修正の候補を作る AI は、さくらか Gemini のままにする。

## 選んだ方針

### 仕組みの形

- サーバーを持たない。道具は、一括処理(ディレクターの PC で動く Node のコマンド)、校正台(Chrome で開く静的な HTML)、移行管理シートの GAS のメニューの3種類にする(`ARCHITECTURE.md` は、GAS の書き出しと書き戻し、FTP へ上げる作業を分けて、部品を5つと数えている)。利用者が1人なので同時編集を受けるサーバーが要らず、1万ページの処理は止まったところから再開できるコマンドの方が扱いやすいため。
- データは共有ドライブの案件のフォルダに、ページごとのファイルと案件ごとの集計ファイルで置く。ファイルごとに、書く部品を1つに決める。
- シートへの書き戻しは、シートに付けた GAS のメニューから、ディレクターが自分の権限で行う。PC から GAS を呼ばないので、鍵や認証の置き場が要らない。
- 部品とコマンドは、業務の流れの順に、することの名前で呼ぶ(取得、型のまとめ、本処理、校正台、書き出し、確かめ、取り直し、比べ合わせ)。「Goal 1」「Goal 2」などの番号の名前は使わない。

### 確認の進め方

- 一括処理が、ページごとに確認の深さを「しっかり確認」「さっと確認」「確認不要」の3つに分ける。表、見出し、リスト、意味に関わる直しは必ずしっかり確認に回し、構造を変える候補は自動で採用しない。
- 確認不要に入れてよいルールは、初めは空にし、試走と取込回で「そのまま採用が 99% 以上、害のある候補が0件」を満たし、性質として意味を変えないものだけを足す。確認不要のページも、一部を抜き取ってさっと確認に回す。このしきい値と抜き取りの割合は、ユーザーの確認待ちである。
- 同じテンプレートのページは、構造の型にまとめ、型ごとに本文の範囲をディレクターが一度だけ承認する。
- 取込回ごとに、一括処理、確定、書き出し、取り込み、移行後チェックを小さく回す。1回目の取込回の実測で、2回目以降の大きさと日程を決め直す。

### CMS への取り込み

- 取込環境の「複数行HTML内素材処理」は「そのまま」にする。「素材型に移動」では、表の中のリンクと画像が外に出され、様式の一覧のような表の意味が壊れるため。この設定は案件ごとの取込環境のもので、ディレクターが設定する。
- 画像と PDF は、直した HTML の中では旧サイトの URL のまま残し、FTP には写さない(FTP 側の容量のため)。取込環境の「取得素材ドメイン」に旧サイトのサーバを入れ、CMS に旧サイトから取得させて素材にする。旧サイトの公開は、移行が終わったあとに終える調整をしている。
- 移行するページへのリンクを FTP 上の URL に書き換えるのは、取込環境で部品に分ける設定が有効な案件の、CMS で部品になる「リンクだけの段落」のリンクに限る。それ以外の内部リンクは旧 URL のまま書き出し、移行後チェックで見つけて移行業者が直す。FTP 上の URL が公開ページに残るのを避けるため、迷うものは書き換えない側に倒す。
- 取り込みで文字が消えたり増えたりする書き方(電話番号のリンク、リンクの中のタグ、ファイルの種類と容量の表記など)は、一括処理が候補として出し、取り込む前に直す。CMS が受け付けるタグと属性は、CMS 取込試験(`docs/cms-import-tag-test/`)で確かめ、取込環境が新しくなるたびに試験をやり直す。
- 取り込んだあとに、取り込んだページを旧ページと確定した HTML と比べる。取り込みの直後と移行後チェックの2回行い、取り込みの崩れと移行業者の手直しを分けて数える。

### データの扱い

- 旧サイトの本文を Anthropic に送らない。一括処理は画面と記録に件数と ID と理由だけを出し、Claude Code には案件のフォルダの中身を開かせない。
- 本文を AI(さくらか Gemini)に送ることは、移行計画書で自治体の同意を確かめる。
- AI の鍵と Google の認証は、PC の環境変数か gcloud の認証に置き、案件のフォルダにもこのリポジトリにも置かない。FTP に上げる作業はディレクターの FTP の道具に任せ、CMS のログインの情報は一括処理と Claude Code に渡さない。

### 今の資産

- 活かす: 候補のエンジン、miChecker 互換エンジン(223 件のパリティ)と比較画面、本文抽出の汎用の判定、AI の呼び出しの部品、共通のルール(`a11y-migration-kb/`)、テスト群。
- 手放す: サーバーでの配信と中継、Cloud Run、Windows 版 `.exe`、npm 依存ゼロの縛り、今の一括の画面とページ単位の確認画面。
- 今の画面は、リニューアルの試走が終わるまで残す。本番のセキュリティの穴は、リニューアルとは別に今の構成で先に塞ぐ。

## 選ばなかったもの

- FTP に画像と PDF を写して素材にする案。FTP 側の容量のため。
- 取込環境の「素材型に移動」。表の意味が壊れるため。
- AI で確認の深さを決めたり、ルールを省いたりすること。共通のルールは、すべてのページに決まった手順でかける。
- 作業者と承認者がアプリを開く形。利用者をディレクターに絞った。
- エンジンを Node 単体(jsdom など)に移すこと。DOM の振る舞いの差で、miChecker 互換テスト(223 件)と出力テストをやり直すことになるため、Playwright の Chromium の中で動かす。
- FTP へ上げる作業を一括処理から行うこと。FTP の接続先と認証を PC の外に置きたくないため。

## 調べていること

KB のルール検索に埋め込みモデル EmbeddingGemma 2 を使えるかを、別の作業で調べている(`memory/embeddinggemma2-kb-search-2026-10.md`)。
ディレクターが文章で尋ね、関係するルールを探す使い方を想定している。

2026-10-07 時点で分かっていることは、次のとおり。

- 言い換えた質問に強く、上位3件に正解が入る割合は、文字の一致で探す方式の81%から92%に上がった。1位の正解率はほぼ同じなので、候補を3件ほど出してディレクターが選ぶ使い方に向く。
- API では提供されておらず、使うならディレクターの PC で動かす。ページの内容を外に送らず、費用もかからない。会社の PC に動かすための道具を入れてよいかは、確かめていない。
- 評価の質問はエージェントが作ったもので、ディレクターの実際の尋ね方とは違う可能性がある。

リニューアルに入れるかは、まだ決めていない。
まず、文章で尋ねてルールを探す画面を作るかを決める。
作るなら、ディレクターの実際の質問で評価し直し、Gemini Embedding 2 とさくらの埋め込みとも比べてから、検索の仕組みを選ぶ。

## 決まっていないこと

決まっていないことは、`ARCHITECTURE.md` の「決めてほしいこと」と、`FLOW.md` の「決まっていないこと、確かめること」にまとめてある。
大きなものは次の5つである。

- 内部リンクの変換を、いつ、どの範囲で確かめるか。変換のボタンは取込環境全体を対象に動くので、取込環境を使う人と押す時期を決める必要がある。
- 1万ページの案件が期間に収まるか。しっかり確認の割合の推測では収まらないので、一括処理の試走で実際の割合と時間を測る。
- 本文を AI に送ることの同意が取れない案件の扱い。`ARCHITECTURE.md` には、AI を呼ぶ候補を止めてルールだけで動かす案がある。
- 取込回ごとの取り込み日を誰が指定し、案件の期間中に何回取れるか。取込回の数と日程は、この枠で決まる。
- 移行管理シートの「AI 修正」タブの列と、シートの版が上がったときの引き継ぎ。
