# CMS 取込試験(許可されるタグと属性の確認)

FTP に置いた HTML を SMART CMS が取り込んだとき、どのタグ、属性、style の指定が残り、どれが消えたり変わったりするかを確かめるための試験ページと照合画面である。
結果は、一括処理が出力する HTML の形(何を残し、何を書き換えるか)を決める根拠にする。

## 背景

2026-10-05 に、取込環境で次のことを確かめた(ユーザーによる試験取込)。

- HTML は断片(html、head、body の無いもの)のままで取り込める。
- 画像と PDF は、旧サイトの絶対 URL のままで取り込まれる。このときは、取り込みの設定の「取得素材ドメイン」が空だった。移行元 URL が FTP 上の URL なので、旧サイトは別のサーバになり、素材として取り込まれなかったと考えられる。
- `#id` を使ったページ内アンカーは残らない。KB の「ページ内アンカーリンク」(`a11y-migration-kb/rules/link/in-page-anchor.md`)が「原則移行しない」としているのと合う。
- 許可されるタグと属性は、まだ分からない。この試験で確かめる。

## ファイル

取込は、ページの中に1か所でも失敗の原因があるとページごと失敗する(`memory/cms-migration-import-failure-patterns.md`)。
そのため、失敗しない想定の項目は 01〜04 に、取込を止めることがある外部リンクは 05 に、失敗しうる要素は原因ごとに 06〜13 に分けた。
06〜13 のどれかが失敗しても、どの原因で失敗したかが1回の取込で分かる。
14 は「画像と PDF を素材にする設定の確かめ」だけで使う。

## 試験用サイト

実在する旧サイトのページ、画像、ファイルを探さなくて済むように、旧サイトの役をする試験用サイトを `test-site/` に用意した。
中身は、実在する自治体のサイトとは関係のない、試験のためだけのページとファイルである。
`test-site/` を Web で見られる置き場に上げ、その URL を照合画面の「試験用サイトの URL」に入れると、YouTube 以外の印がすべて埋まる。

置き場によって、確かめられることが変わる。
CMS は、移行元 URL と同じサーバの画像とファイルを素材にするので、試験用サイトを試験ページと同じサーバに置くか、別のサーバに置くかで、画像とファイルの扱いが変わるため。

| 置き場 | 確かめられること | 確かめられないこと |
| --- | --- | --- |
| 試験ページと同じ FTP のサーバ(別のフォルダ) | タグと属性の残り具合。同じサーバの画像とファイルが素材になるか | 「取得素材ドメイン」の効き方(本番の旧サイトは FTP と別のサーバなので、本番と条件が違う)。12 と 13 の、取得素材ドメインが空のときの結果(同じサーバなので SVG と WebP も取りに行く) |
| FTP と別のサーバ | タグと属性の残り具合。「取得素材ドメイン」が空のときと、試験用サイトのサーバを入れたときの、画像とファイルの扱い(本番と同じ条件) | ― |

別のサーバが用意できるなら、そちらに置く。
用意できなければ、同じ FTP のサーバの別のフォルダに置き、「画像と PDF を素材にする設定の確かめ」は、別のサーバを用意できたときに行う。

## 手順

1. `checker.html` を Chrome で開く。
2. `test-site/` を置き場に上げ、「1. 準備」の「試験用サイトの URL」にその URL を入れて「試験用サイトで埋める」を押す。YouTube の埋め込み URL だけは手で入れる。実在する旧サイトの URL を1つずつ入れてもよい。01〜13 をすべて選んで「置き換えて保存する」を押す。名前の末尾に `-ready` の付いたファイルがダウンロードされる。Chrome が「複数ファイルのダウンロード」を許可するか尋ねたら、許可する。実在する旧サイトの URL を使い、webp が旧サイトに無ければ、13 は選ばない。
3. `-ready` の付いたファイルを FTP の試験用の置き場に上げる。
4. 移行管理シートの取込データに試験用の行を足し、移行元 URL に FTP 上の URL を入れて取り込む。行の他の列は、案件の試験用の行に合わせる。
5. 行ごとに、取込の結果(取込シートの「結果」と「エラー内容」の列)を控える。05 で取込が止まったら、止めた時刻を控える。
6. 取り込めたページのプレビュー URL を Chrome で開き、Ctrl+S で「ウェブページ、HTML のみ」を選んで保存する。「取り込み範囲プレビュー」の HTML を保存してもよい。
7. `checker.html` の「2. 照合」で、手順3で上げた `-ready` のファイルと、手順6で保存した HTML を選んで「照合する」を押す。
8. 「項目ごとの結果」と「タグと属性の残り具合」の CSV を保存する。

## 画像と PDF を素材にする設定の確かめ

リニューアルでは、直した HTML の画像と PDF を旧サイトの URL のままにし、取り込みの設定の「取得素材ドメイン」に旧サイトのサーバを入れて、CMS に素材として取り込ませる(`docs/renewal/ARCHITECTURE.md` の「画像とファイル」)。
上の手順とは別に、次を1回行う。

1. 試験用の取込環境で、取得素材ドメインに試験用サイト(FTP と別のサーバに置いたもの)のサーバを入れる。
2. `04-media-ready.html` を、上の手順とは別の移行管理 ID で取り込む(同じ移行管理 ID では、CMS が HTML を取得し直さないため)。
3. 取り込んだページの画像とファイルのリンクが CMS の素材の URL に変わったこと、CMS の素材の一覧に入ったこと、ファイルの大きさが0でないことを確かめる。結果が「完了」でも、取込シートの「エラー内容」を控える。
4. `12-risky-svg-file-ready.html` と `13-risky-webp-file-ready.html` も、それぞれ別の移行管理 ID で取り込み、結果とエラー内容を控える。取得素材ドメインが空のときは SVG と WebP を取りに行かないので、取り込みでつまずくかどうかは、この状態でしか分からない。
5. `14-external-image.html`(外部のサーバの画像を1枚だけ入れた小さな HTML)を、置き換えずに FTP の試験用の置き場に上げ、別の移行管理 ID で取り込む。外部の画像は、FTP とも試験用サイトの置き場とも別のサーバに置く必要があるので、このリポジトリの GitHub の URL を使う。取りに来るプログラムの種類で断らないサーバにするため。04 に混ぜないのは、外部の画像が取りに行かれて取得に失敗すると、04 のページ全体が登録されず、手順3が確かめられなくなるため。外部の画像が素材になったか、元の URL のまま残ったか、取得に失敗してページが登録されなかったか(取込シートの結果とエラー内容)を記録する。素材になった場合は、一括処理の事前の確かめの対象に外部のサーバの画像も含める(`docs/renewal/ARCHITECTURE.md` の「一括処理が前もって確かめること」)。

同じサイトとグループで一度取り込んだ URL の素材は、次の取り込みで再利用される。試験を繰り返すときは、前回の素材を消すか、素材の登録日時で見分ける。

## 結果の読み方

| 判定 | 意味 |
| --- | --- |
| そのまま | 元と同じ。半角の空白の違いは見ないが、全角空白、`&nbsp;`、`pre` の中の空白は見る。 |
| 囲みだけ違う | 元にあったものが何も減っておらず、`div`、`section`、`article` の囲みを外すと同じ。CMS がパーツの囲みを足した場合など。 |
| 変化あり | タグ、属性、文字のどれかが変わった。「減ったもの」「増えたもの」の列と、元と取込後の HTML を見る。 |
| 消えた | 中身が残っていない。 |
| 目印なし | 取込後の HTML に目印の段落が無い。ページごと取込に失敗したか、保存した範囲に入っていない。すべての項目が目印なしのときは、保存した範囲か文字コードを疑う。 |

「タグと属性の残り具合」は、タグ(`table`)、属性(`th@scope`)、style の指定(`span@style:color`)、特別な空白(`文字:nbsp`、`文字:全角空白`)ごとに、項目の中での出現数を取込の前と後で比べる。
同じ項目に同じタグが2つあって1つだけ落ちた場合も、減ったものとして数える。
残った割合の低いものから並ぶ。

取込後に終わりの目印(`T0199` など)が無いときは、そのページの最後の項目は目印を囲む要素の終わりまでを中身として比べ、試験の内容の欄にその旨を書く。

## 結果の置き場所

保存した CSV と取込後の HTML は、このフォルダの `results/<試験日>/` に置く。
結果をもとに、CMS が受け付けるタグと属性の一覧を `a11y-migration-kb/cms/` に足し、一括処理の出力をそれに合わせる。
