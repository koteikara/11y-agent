# CMS 取込試験の結果(2026-10-07)

試験ページ 01〜14 を CMS の取込環境に取り込み、取り込んだあとのページの本文を、照合画面で元の HTML と比べた結果である。
取込環境の URL、FTP の URL、CMS の素材のパスは、公開リポジトリなので載せていない。
照合画面が出した CSV(項目ごとの結果、タグと属性の残り具合)はそれらの URL を含むので、ユーザーの手元に置き、ここには要約だけを置く。

## 試験のしかた

- 試験ページの旧サイトの役は、`test-site/` を個人のサーバ(FTP とも CMS とも別のサーバ)に置いて務めた。
- 1回目は取得素材ドメインを空にして 01〜13 を、2回目は取得素材ドメインに試験用サイトのサーバを入れて 04、12、13、14 を、別の移行管理 ID で取り込んだ。05(外部リンク)は、取り込みが止まるおそれがあるので、まだ取り込んでいない。
- 取り込んだあとの本文は、CMS のプレビューの本文の部分を保存して比べた。プレビューは公開側の見た目で描くので、見出しを包む `span`、表の横スクロールの部品、リンクの部品の `class` など、公開側のテンプレートが足すものが増えている。それらは CMS が保存した本文の変化ではないので、下の要約では扱わない。

## 取込環境の取り込みの設定

この環境の取り込みの設定は次のとおりだった。
取り込みの振る舞いはこの設定で変わるので、別の案件では設定を確かめてから読む。

| 設定 | 値 |
| --- | --- |
| 取得範囲 | ID `content`(試験ページは断片なので当たらず、ファイル全体が範囲になった) |
| 除外範囲 | タグ `h1`、ほかに ID とクラスがいくつか |
| 各項目挿入(部品に分ける) | する |
| 複数行HTML内素材処理(文中のリンクと画像を外に出す) | 素材型に移動 |
| テーブル分解 | しない |
| 取り込み素材ファイル名 | そのまま |
| 取得素材ドメイン | 1回目は空、2回目は試験用サイトのサーバ |

## わかったこと

### 文字が消えるもの

取り込みのエラーにならず、文字ごと消える。
気づきにくいので、一括処理が前もって直す。

- 電話番号のリンク(`a href="tel:…"`)は、番号の文字ごと消えた。
- `href` の無い `a` と、`href="javascript:…"` の `a` は、リンクの文字ごと消えた。
- 本文の `&lt;tag&gt;` は、タグとして読まれて消えた(`&amp;` と `"` は残った)。
- インラインの `svg` は、要素ごと消えた。

### 文字が増えるもの

- 段落の中の画像は、画像の部品として段落の外に出され、元の場所には代替テキストが文字として入った(例: 2枚の横並びの段落が「横並びの1枚目横並びの2枚目」という文字になった)。
- 段落、箇条書き、表の中のリンクは、リンクの部品として外に出され、元の場所には文字だけが残った。リンクの文字が二重に読める。
- ファイルのリンクには、CMS が「(PDFファイル: 30.2KB)」のような種類と容量を書き足した。元の文字にある「(PDF:120KB)」のような容量の表記は、そのまま残って二重になった。

### リンク

- ふつうのリンクは「テキストリンク」の部品になり、すべて `target="_blank"`(新しいウィンドウで開く)が付いた。
- ページ内リンク(`#id`)は、`移行元URL#id` の外部リンクになった。
- 相対パスのリンクは、移行元 URL(FTP)を基準にした絶対 URL になった。
- `title`、`aria-label`、リンクの中の `strong` は消えた。
- `name` のアンカーは消えた。

### 見出し

- `h1` は中身ごと消えた(除外範囲のタグ `h1` による)。
- `h2` が無いページでは、`h3` が `h2` に繰り上がった。
- 見出しの `id` は残った。見出しの中の `strong` は消えた。

### 残ったもの

`p`、`br`、`strong`、`em`、`b`、`i`、`u`、`small`、`sup`、`sub`、`q`、`cite`、`blockquote`、`pre`、`ul`、`ol`(`start`)、`li` の中の段落、`dl`、`dt`、`dd`、`span lang`、`table`、`caption`、`thead`、`tbody`、`tfoot`、`th scope`、`colspan`、`rowspan`、YouTube と地図の `iframe`。

### 形を変えて残ったもの

- 段落の `lang` は、`<span lang="en"><p>…</p></span>` のように外から包む形になった。
- `align="center"` は `style="text-align: center;"` になった。`center` 要素も段落になった。

### 消えたもの(中の文字は残る)

- 要素: `s`、`del`、`ins`、`mark`、`abbr`、`time`、`kbd`、`samp`、`var`、`dfn`、`ruby`(`rt`、`rp` も)、`bdi`、`bdo`、`wbr`、`hr`、`address`、`section`、`article`、`aside`、`main`、`header`、`footer`、`nav`、`details`、`summary`、`figure`、`figcaption`(説明は別の段落になる)、`div` の入れ子、`font`、`video`、`audio`、`object`、`embed`、`canvas`、`math`、`script`、`style`、`noscript`、フォームの部品。
- 属性: `class`、`id`(見出し以外)、`style`(`text-align` 以外)、`title`、`role`、`aria-*`、`data-*`、`hidden`、`tabindex`、`dir`、`ol type`、`ol reversed`、`li value`、表の `headers`、`th` の `id` と `abbr`、`colgroup`、`col`、表の古い属性(`summary`、`border`、`width` など)、セルの `style`、画像の `width`、`height`、`title`、`loading`。
- 表のセルの中の `h3` は、見出しでなくなった。
- 空の段落は1つに詰められた。

### 画像とファイル

- 取得素材ドメインが空のとき、移行元 URL(FTP)と別のサーバの画像は素材にならず、`data-foreign-domain` の印が付いて元の URL のまま残った。その画像が画像の部品に振り分けられると、ページ全体が「エラー」になった(04)。
- 取得素材ドメインに試験用サイトのサーバを入れると、画像 23 枚と PDF、Excel、Word がすべて CMS の素材になった(2回目の 04)。同じ URL の画像とファイルは、1つの素材が使い回された。
- 取得素材ドメインに入れていない別のサーバ(GitHub)の画像も、素材になった(14)。取得素材ドメインに何かを入れると、ほかのサーバの画像も取りに行くと考える。
- SVG と WebP の画像ファイルは、素材として取りに行くと「画像の登録に失敗しました」になり、ページ全体が「エラー」になった(2回目の 12、13)。取得素材ドメインが空のときは取りに行かないので、元の URL のまま残って「完了」になった(1回目)。
- `alt` 属性の無い画像は、`alt=""`(装飾の画像)になった。意味のある画像でも、黙って装飾の扱いになる。
- `data:` の画像は、`src` が消えた。
- 画像ファイルへの文字のリンクは、ファイルのリンク(JPEG)の部品になった。

### 取込ツールの操作

- 取り込み用の CSV は、22列の見出しの名前と並びが一致し、Shift_JIS で保存したものが通った。移行先カテゴリは「ホーム/」から始まるパンくずの書き方で通った。素材保存先グループは、存在するグループの名前(試験では「共通」)でないと、その行がチェック NG になった。
- 解析、登録、取り込みの設定の保存の前に、ブラウザの確認ダイアログが出る。
- 「チェックした情報を登録する」で一度に処理されたのは 10 件までだった。10 件を超えて選ぶと、残りは処理されない。1回の登録は 10 件以下にするか、残った行を選び直して押し直す。

## まだ確かめていないこと

- 取得できない画像とファイル(404)の扱い。
- 内部リンクの変換(「内部リンクを設定する」)。
- 部品に分けない設定(各項目挿入: しない)と、文中のリンクと画像を外に出さない設定(複数行HTML内素材処理: そのまま)での振る舞い。
- CMS の公開前のチェック(強制アクセシビリティチェック)で止まる項目。
