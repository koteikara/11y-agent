# CMS 取込試験の結果(2026-10-07)

試験ページ 01〜14 を CMS の取込環境に取り込み、取り込んだあとのページの本文を、照合画面で元の HTML と比べた結果である。
取込環境の URL、FTP の URL、CMS の素材のパス、環境の名前は、公開リポジトリなので載せていない。
照合画面が出した CSV(項目ごとの結果、タグと属性の残り具合)はそれらを含むので、試験をした人の手元に置き、ここには要約だけを置く。

## 試験のしかた

- 試験ページの旧サイトの役は、`test-site/` を個人のサーバ(FTP とも CMS とも別のサーバ)に置いて務めた。
- 1回目は、取得素材ドメインを空にして、05 を除く 01〜13 を取り込んだ。05(外部リンク)は、止まるおそれがあるので、最後に単独で取り込んだ。
- 2回目は、取得素材ドメインに試験用サイトのサーバを入れて、04、12、13、14 を、1回目とは別の移行管理 ID で取り込んだ。
- 取り込んだあとの本文は、CMS のプレビューの本文の部分を保存して比べた。プレビューは公開側の見た目で描くので、見出しを包む `span`、表の横スクロールの部品、リンクとファイルのリンクの部品の `class` などが足されている。CMS が保存した本文の変化と、公開側の部品が足したものを分けられないものは、そのように書いた。

## 取込環境の取り込みの設定

取り込みの振る舞いはこの設定で変わるので、別の案件では設定を確かめてから読む。

| 設定 | 値 |
| --- | --- |
| 取得範囲 | ID `content`(試験ページは断片なので当たらず、ファイル全体が範囲になった) |
| 除外範囲 | タグ `h1`、ほかに ID とクラスがいくつか |
| 各項目挿入(部品に分ける) | する |
| 複数行HTML内素材処理(文中のリンクと画像を外に出す) | 素材型に移動 |
| テーブル分解 | しない |
| 取り込み素材ファイル名 | そのまま |
| 旧 CMS からの移行用の取り込み方(地図の部品のキーが空でないと有効になる) | 有効。これが有効なときは、`p`、`iframe`、見出しと `a` の `id` が残る。無効な案件では消える見込み(試験で確かめる) |
| 取得素材ドメイン | 1回目は空、2回目は試験用サイトのサーバ |

## わかったこと

### 文字が消えるもの

取り込みのエラーにならず、文字ごと消える。

- 電話番号のリンク(`a href="tel:…"`)は、番号の文字ごと消えた。
- `href` の無い `a` と、`href="javascript:…"` の `a` は、リンクの文字ごと消えた。
- 本文の `&lt;tag&gt;` は、タグとして読まれて消えた(`&amp;` と `"` は残った)。
- インラインの `svg` は、要素ごと消えた。

### 文字が増えるもの

- 段落の中の画像は、画像の部品として段落の外に出され、元の場所には代替テキストが文字として入った(例: 2枚の横並びの段落が「横並びの1枚目横並びの2枚目」という文字になった)。`alt=""` の画像は、文字が入らず、段落ごと画像の部品になった。
- 段落、箇条書き、表の中のリンクは、リンクの部品として外に出され、元の場所には文字だけが残った。リンクの文字が二重に読める。
- ファイルのリンクには、プレビューで「(PDFファイル: 30.2KB)」のような種類と容量が付いていた。公開側のファイルのリンクの部品が表示しているもので、保存された本文に入っているかは分けていない。元の文字にある「(PDF:120KB)」のような容量の表記は、そのまま残って二重に表示された。

### リンク

- ふつうのリンクは「テキストリンク」の部品になり、プレビューでは `target="_blank"`(新しいウィンドウで開く)が付いていた。PDF などのファイルのリンクにも付いた。画像ファイルへのリンクには付かなかった。部品の設定か公開側の描画かは分けていない。
- ページ内リンク(`#id`)は、`移行元URL#id` の外部リンクになった。
- 相対パスのリンクは、移行元 URL(FTP)を基準にした絶対 URL になった。
- `title`、`aria-label`、`rel`、`lang`(リンクの属性)、リンクの中の `strong` は消えた。
- `name` のアンカーは消えた。

### 見出し

- `h1` は中身ごと消えた(除外範囲のタグ `h1` による)。
- `h2` が無いページでは、`h3` が `h2` に繰り上がった。表のセルの中の `h3` も、セルの中のまま `h2` に繰り上がって残った。
- 見出しの `id` は残った(上の「旧 CMS からの移行用の取り込み方」が有効なため)。見出しの中の `strong` は消えた。

### 残ったもの

- 要素: `p`、`br`、`strong`、`em`、`b`、`i`、`u`、`small`、`sup`、`sub`、`code`、`q`、`cite`、`blockquote`(`cite` 属性も)、`pre`、`ul`、`ol`(`start`)、`li` の中の段落、`dl`、`dt`、`dd`、`span lang`、`table`、`caption`、`thead`、`tbody`、`tfoot`、`th scope`、`colspan`、`rowspan`、表の `summary`。
- `iframe`(YouTube と地図): `src`、`title`、`width`、`height` は残り、`loading` と `allowfullscreen` は消えた。
- `p`、`iframe`、見出しの `id` が残ったのは、「旧 CMS からの移行用の取り込み方」が有効なためと考えられる。

### 形を変えて残ったもの

- 段落の `lang` は、`<span lang="en"><p>…</p></span>` のように外から包む形になった。
- `align="center"`(段落と表)は、`style="text-align: center;"` になった。`center` 要素も段落になった。

### 消えたもの(中の文字は残る)

- 要素: `s`、`del`、`ins`、`mark`、`abbr`、`time`、`kbd`、`samp`、`var`、`dfn`、`ruby`(`rt`、`rp` も)、`bdi`、`bdo`、`wbr`、`hr`、`address`、`section`、`article`、`aside`、`main`、`header`、`footer`、`nav`、`details`、`summary`、`figure`、`figcaption`(説明は別の段落になる)、`div` の入れ子、`font`、`video`、`audio`、`object`、`embed`、`canvas`、`math`、`script`、`style`、`noscript`、フォームの部品。
- 属性: `class`、`id`(見出し以外)、`style`(すべて。`text-align` を含む)、`title`、`role`、`aria-*`、`data-*`、`hidden`、`tabindex`、`dir`、`ol type`、`ol reversed`、`li value`、表の `headers`、`th` の `id` と `abbr`、`colgroup`、`col`、表の古い属性(`border`、`width`、`bgcolor`、`cellpadding`、`cellspacing`)、セルの `style`。
- 画像の `width`、`height`、`title`、`loading` は、画像の部品に出された画像では消えた(画像ファイルへのリンクの中のサムネイルでは `width` が残った)。
- 中身の無い `<p></p>` は消え、`&nbsp;` だけの段落は残った。

### 画像とファイル

- 取得素材ドメインが空のとき、移行元 URL(FTP)と別のサーバの画像は素材にならず、`data-foreign-domain` の印が付いて元の URL のまま残った。
- 取得素材ドメインに試験用サイトのサーバを入れると、04 の画像 22 枚と PDF、Excel、Word がすべて CMS の素材になった。同じ URL の画像とファイルは、1つの素材が使い回された。
- 取得素材ドメインに入れていない別のサーバ(GitHub)の画像1枚も、素材になった(14)。同じ名前の素材がすでにあったので、乱数の付いた名前で登録された。
- SVG と WebP の画像ファイルは、素材として取りに行くと「画像の登録に失敗しました」になり、ページ全体が「エラー」になった(2回目の 12、13)。
- `alt` 属性の無い画像は、`alt=""`(装飾の画像)になった。意味のある画像でも、黙って装飾の扱いになる。
- `data:` の画像は、`src` が消えた。
- 画像ファイルへの文字のリンクは、ファイルのリンク(JPEG)の部品になった。

### 取込ツールの操作

- 取り込み用の CSV は、22列の見出しの名前と並びが一致し、Shift_JIS で保存したものが通った。移行先カテゴリは「ホーム/」から始まるパンくずの書き方で通った。素材保存先グループは、取込環境に存在するグループの名前でないと、その行がチェック NG になった。
- 解析、登録、取り込みの設定の保存の前に、ブラウザの確認ダイアログが出る。
- 試験では、「チェックした情報を登録する」で 12 件を選んだところ 10 件で止まり、残りの 2 件は処理されなかった。残りを選び直して押し直すと処理された。上限の決まりは調べていない。

## まだ確かめていないこと

- 応答しないサーバへのリンクで取り込みが止まるか。
- 取得できない画像とファイル(404)の扱い。
- 内部リンクの変換(「内部リンクを設定する」)。
- 部品に分けない設定(各項目挿入: しない)、文中のリンクと画像を外に出さない設定(複数行HTML内素材処理: そのまま。表、段落、箇条書きの中は下の追加の試験で確かめた。内部リンクの変換は未確認)、旧 CMS からの移行用の取り込み方が無効な設定での振る舞い。
- `&amp;lt;` のように二重に書いた `<` `>` が、文字として残るか。
- CMS の公開前のチェック(強制アクセシビリティチェック)で止まる項目。

## 追加の試験: 表の中の画像とファイルのリンク(15)

表の中の画像とリンクが想定どおりに取り込まれないことを確かめるため、試験ページ 15 を、取り込みの設定の「複数行HTML内素材処理」を変えて2回取り込んだ。
どちらも取得素材ドメインに試験用サイトのサーバを入れ、ほかの設定は上の表のとおりにした。
試験のあと、設定は元に戻した。

| 表の中の形 | 素材型に移動 | そのまま |
| --- | --- | --- |
| 行ごとにファイルのリンクがある表(様式の一覧) | セルには文字だけが残り、リンクは表の下にファイルのリンクの部品として並んだ。どの行のファイルか、表から分からなくなる | セルの中に、素材のファイルへのリンクとして残った |
| 1つのセルに2つのリンク | セルは「PDF 版 Word 版」という文字だけになった | 2つともリンクとして残った |
| 文字とリンクが混ざったセル | 文の中のリンクが文字になり、リンクは表の下に出た | 文の中のリンクのまま残った |
| セルの中の画像(説明文のあるセルも同じ) | セルには代替テキストが文字として入り、画像は表の下に画像の部品として出た | セルの中に、素材の画像として残った |
| セルの中のリンク付き画像 | 画像とリンクが別々に表の下に出た | リンクの付いた画像のまま残った |
| セルの中のアイコン付きファイルのリンク | セルに「PDFファイル申請書」という文字が入り、リンクとアイコンの画像が別々に表の下に出た | アイコンとリンクのまま残った |
| セルの中の箇条書きのリンク | 箇条書きは文字だけになり、リンクは表の下に出た | 箇条書きの中のリンクのまま残った |

- 「そのまま」でも、画像とファイルは CMS の素材になり、リンク先と画像の参照先は素材に書き換わった。
- 「そのまま」では、ファイルのリンクに種類と容量の文字(「(PDFファイル: 30.2KB)」)が付かなかった(プレビューの DOM で確認)。容量の属性とファイルの種類のクラスは付くので、公開側の見た目でアイコンが出るかは分けていない。この設定の案件では、リンクの文字に種類と容量を書いておく必要がある。
- 「そのまま」でも、リンクには `target="_blank"` が付いた。
- 「そのまま」で、リンクの中の画像に中身の無い属性(`domain=""`)が残った。
- 段落と箇条書きの中のリンクと画像も、同じ設定で外に出るかどうかが決まる(CMS の取り込みの振る舞いの調べ)。「そのまま」の設定での段落の中のリンク、内部リンクの変換は、まだ確かめていない。

## 追加の試験: 文中のリンクと画像を外に出さない設定での段落と箇条書き(03、04)

試験ページ 03(リンク)と 04(画像とファイル)を、別の移行管理 ID で、複数行HTML内素材処理を「そのまま」、取得素材ドメインに試験用サイトのサーバを入れて取り込み、1回目と2回目(素材型に移動)の結果と比べた。
内部リンクの変換のボタンは、取込環境全体(ほかの人の行を含む)を対象に動くので押していない。内部リンクの変換は、別の取込環境で確かめる。
試験のあと、設定は元に戻し、作ったページはゴミ箱に移した。

| 本文の形 | 素材型に移動 | そのまま |
| --- | --- | --- |
| 文の中のリンク | リンクは文字になり、リンクの部品が段落の後ろに出た | 文の中のリンクのまま残った |
| 箇条書きの中のリンク | 箇条書きは文字だけになり、リンクの部品が後ろに出た | 箇条書きの中のリンクのまま残った |
| 1つの段落に並んだ2つのリンク | 段落は文字だけになり、リンクの部品が2つ出た | 段落の中に2つのリンクのまま残った |
| リンクだけの段落 | リンクの部品になった | リンクの部品になった(同じ) |
| 段落の中の画像(文字と一緒、横並び) | 段落に代替テキストが文字として入り、画像の部品が後ろに出た | 段落の中の画像のまま残った |
| 段落の外の画像 | 画像の部品になった | 画像の部品になった(同じ) |
| 文中のファイルのリンク | 文字になり、ファイルのリンクの部品(種類と容量の文字付き)が後ろに出た | 文の中のリンクのまま残った(種類と容量の文字は付かない) |
| ファイルのリンクだけの段落 | ファイルのリンクの部品(種類と容量の文字付き) | ファイルのリンクの部品(同じ) |
| アイコン画像とリンクを並べた段落 | 文字と、リンクの部品と、画像の部品に分かれた | 段落の中のアイコンとリンクのまま残った |

- 「そのまま」でも、リンクだけの段落、ファイルのリンクだけの段落、段落の外の画像は、部品になった。部品に分ける(各項目挿入: する)設定が効いている。
- 「そのまま」では、ほかの要素を含むリンクの中身が、タグのまま文字として表示された(段落を丸ごと囲むリンクで `<p>`、強調を含むリンクで `<strong>` が、リンクの文字として見えた)。リンクの中には文字だけを入れる。
- どちらの設定でも、画像と文字の両方を含むリンクは、画像のリンクだけになり、リンクの文字が消えた。「そのまま」では、アイコン画像をリンクの中に入れたファイルのリンクも、リンクの文字(「申請書」)が消えた。
- `name` 属性だけの `a`(古いページ内アンカーのリンク先)は、「そのまま」では中身の無いリンクとして残った。
