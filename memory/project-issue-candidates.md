# CMS移行・アクセシビリティ改善：課題候補一覧

作成日：2026年9月17日

## 目的と調査範囲

移行・修正・確認・承認の各工程について、手戻り、情報欠落、品質のばらつきにつながる課題候補を整理する。優先度、根拠、影響、対応案、解消を判断する条件を記載する。

ユーザー提示の前回会話と本リポジトリの資料を参照した。PR #133のレビュー対応では、mainの `8790c64` の資料・関連する検証コードと、未マージのPR #132の状態を照合した。前回のコミット `9991705` と参照資料の同一性は未確認であり、前回PRの差分レビューではない。実装コードの監査、アプリ実行、CMS操作、実ページのアクセシビリティ検査は実施していない。文書に「未実装」とある事項も、現在のコード上の欠陥として断定しない。

対象は新CMSへ登録する本文コンテンツと、その移行業務。旧サイトの外観再現は目的としない。テンプレート起因の問題は本文修正と分けて管理する。行政情報・自治体方針の変更はAIで確定しない。

## 先に具体化する事項

1. **CMSの実入力制約を確定する（A01・A04）**：テキスト、画像、ファイル、リンク、表を含む少数ページで、登録・保存・再編集・プレビューを通して確認する。
2. **ページの完了条件を定義する（C01〜C04）**：「要確認」と検査の未解消項目が、どの状態で誰に渡り、何をもって解決になるかを決める。
3. **本文抽出と意味保持の評価セットを作る（A02・B02・D03）**：期待する本文、除外部分、変更禁止情報、人間確認箇所を付ける。
4. **実案件利用の前提を整える（D01・D02）**：認証・保存・外部送信・プレビュー制限を確認する。それまでは検証用データで進める。

これらは推奨する検討順序であり、実装方針や顧客承認が決定したことを意味しない。
