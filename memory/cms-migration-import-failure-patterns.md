# コンテンツ移行: 機械取込みがうまくいかないパターン（ユーザー共有メモ）

- 記録日: 2026-09-18
- 出所: ユーザー（中川）からチャットで共有された、SMART L-Gov CMS への取込作業の現場知見。
- 位置づけ: 原文のまま記録する。設計や課題化はまだ行っていない（別途 project-issue-candidates.md への反映を検討）。
- 注記（ユーザーより）: リンク先URLは not found になっているもの、更新されているものもあるが、CMS側で取込履歴が残っている可能性があるのでそのまま掲載する。

## 1. 取り込めない／取り込めてもパーツにハマらない発生条件

### ファイルリンクやリンクが WYSIWYG に入ってしまう
- 条件: リストの中にリンク／ファイルリンクがある時、「リスト＝WYSIWYG」が優先されてしまう。
- 取込前: https://www.town.koryo.nara.jp/contents_detail.php?co=kak&frmId=5993
- 取込後: https://www01.migrate.smart-lgov.jp/torikomi/77/koryo/6822.html

### ファイルリンクが、リンク付き画像で取り込まれてしまう
- 条件: アイコン画像がリンク前にある時、アイコン画像を除外指定していなければ発生することがある。除外指定していれば発生しない。
- 条件: ファイルリンクにアイコンが組み込まれている（CSSではなく直接 img タグでアイコンがついている）形式の場合に、テキストリンクが除去されアイコンのみが移行される。
- 取込前: https://www.town.tochigi-nakagawa.lg.jp/life/kosodate_kyouiku/2025-0324-1009-105.html
- 取込後: https://www01.migrate.smart-lgov.jp/torikomi/78/nakagawa/9319.html

### 取込元の HTML が特殊なため取り込めない: ファイルの拡張子が URL に含まれない
- 取込前: https://www.town.tochigi-nakagawa.lg.jp/life/fukushi_kaigo/2020-0219-1001-25.html
- 取込後: https://www01.migrate.smart-lgov.jp/torikomi/78/nakagawa/9313.html
- 原因: 画像URLが `data:image/png;base64,/9j/4A....` となっており、拡張子が png でないため画像として取り込まれない。

### 取込元の HTML が特殊なため取り込めない: CSS 側で画像表示している
- 条件: 画像が HTML ではなく CSS の背景画像として表示されているため取り込めない（コンテンツの一部なので要取込）。
- 移行元: https://www.town.wake.lg.jp/children/englishQuiz/
- 取込後: http://www03.migrate4.smart-lgov.jp/torikomi_test/77/wake/239.html

### SMART L-Gov CMS 非対応形式のファイル
- 非対応形式のファイルのため、取り込めず／手動アップも出来ず。
- 例 ODT 形式: https://www.townkamiita.jp/docs/2013103000011/
- 例 webp 画像: https://iju.go-iijima.nagano.jp/information/4847/

### 取込元の HTML が特殊なため取り込めない: DOM で書かれている
- （具体例なし。JavaScript で DOM を組み立てているページと解釈）

### 画像やファイルの URL 末尾に不要なソースがあるために画像・ファイルとして認識されない
- 取込前: https://kamisu-pr.jp/2021/11/10/r3senningarou/
- 取込後: http://www01.migrate.smart-lgov.jp/torikomi/77/kamisushi_kamisumika_pre/5833.html
- 原因: `file_size="250104"` や `data-foreign-domain=""` といった不要な属性が入っている。

## 2. 実際のページ取込で起きるよくあるエラー（頻度の高い順）

### ① Not found のファイルや画像
- ページ内に not found の画像やファイルがあるとエラーとなり、ページとしては取込に失敗する。
- 現状: エラー検出後に手動で対象箇所のファイルを1つずつ削除して取り込んでいる。
- 要望: 自動的にリンクを除去して取り込んでほしい（ファイルテキストはテキストとして取り込むべきかは要検討）。

### ② SVG 画像ファイルが検出されない
- 画像として検出されず、それでいて取込時に画像登録失敗エラーとして検出される。
- いままさに遠野市で起きている: https://www.city.tono.iwate.jp/index.cfm/45,43562,242,472,html

### ③ 外部リンク系（取込負荷への影響が大きい）
- 主に「ふるさと納税（さとふる等）」や「Adobe Reader ダウンロード」といった特定の外部リンクがあるページは、取込時にエラーにもならず数万秒作業をし続ける状態になるため強制停止している。
- 強制停止するため、裏で取込成功したページがのちに登録されており、二重登録が問題にもなっている。
- 上記2つは明確に確認済み。稀に別のサイトでも同様の現象が起きているので、共通点として「外部リンク」と表現している。

### ④ 機種依存文字
- ページ内に機種依存文字（規格外の文字コード？ 縦長の長方形っぽい見た目になるもの）が含まれていると取込結果がエラーとなり取り込めない。
- ここ数年は見なくなっている（何かしらのバージョンアップで副作用的に解消された可能性）。数年前までは非常に多くのエラーを検出していた。
- ページ内で原因の文字を探す難易度が高く、ざっくりそれっぽい箇所を削除して取り込んでいた。事前に検知できるとスムーズ。

## 3. 「これが出来るとだいぶスピードアップできる」系

### 画像が複数横並びになっている時、2枚並びまたは3枚並びのパーツに取り込む
- HTML複数行に取り込まれる素材は「外に出す」設定で外に出せるが、画像だけはファイル・リンクと違って「横並び」系のパーツがあるため、パーツの入れ直し作業が発生する。
- 横並び画像であることを判定でき、さらに2枚並び・3枚並びのどれにあたるかも判定できれば、画像の多いページでの入れ替え作業をまるごと無くせる（「時間がかかるページ」の一角）。

### ファイルリンクは、表の中か否かで取り込み方を変えられる
- 「外に出す」設定で取り込んだ時に困るのが表内にあるファイルリンクで、外に出たファイルリンクを表内で再設定（入れ直す）作業が発生する。
- 表内ファイルを優先するなら「外に出さない」設定が望ましいが、全部が表内ファイルというわけではない。
- 要望: 「基本は外に出すが、表内にあるリンク・ファイルリンクは出さない」という取り込み方を案件ごとに選択できると、表内のファイルリンクの入れ直し作業を無くせる。

### HTML複数行内ファイルリンクにファイル種別と容量表示を追加する
- ファイルリンクパーツは自動的に「（PDF：20.3MB）」のようにファイル種別と容量を表示するが、HTML複数行内に取り込まれたファイルリンクには自動表示されないため、再度ファイル挿入し直している（ファイル挿入するとリンクテキストの一部として表示される）。
- 自動表示されるなら、取り込まれた状態からリンクテキストを適切な文字列に打ち換えるだけで（ほぼ）済む（「時間がかかるページ」の一角）。
