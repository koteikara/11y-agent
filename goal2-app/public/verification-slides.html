移行方式の比較検証

移行作業はこう変わる
前回（佐賀市）との違い

同じページを3つのやり方で作業し、かかった時間と品質を比べます。
この資料は、実際に作業するみなさん向けに「何が変わるのか」をまとめたものです。

対象ツール: アクセシビリティ候補レビュー（goal2-app）／詳しい手順は 検証作業ガイド

一番の違い

人が目視で確認するタイミングが、1つ前になる

AIを使うことは前回も同じです。変わるのは「AIの結果を、取り込む前に人が確認するかどうか」です。

前回（佐賀市）

AIが最適化するAIがアクセシビリティ対応済みのHTMLを作る
→
取り込むそのHTMLをCMSに取り込む
→
人が目視で確認しながら作業取り込んだ後に確認する

今回

AIが提案するAIは修正候補を出すところまで
→
人が目視で確認して
最適化HTMLを作るこの工程が増える
→
取り込む人が確認したHTMLを取り込む
→
人が目視で確認しながら作業ここは前回と同じ

増えるのは青い枠の1工程だけです。取り込んだ後の作業は、これまでどおりです。

なぜ変えるのか

前回は「無駄な修正」が発生していた

AIの結果をそのまま取り込んでいたため、良し悪しに気づくのが取り込んだ後になっていました。

前回起きていたこと

直しすぎ・間違い

AIが直した結果を、最適化される前の状態に戻す作業が発生した

漏れ

AIが拾えていなかった箇所を、後から探して直す必要があった

どちらも、取り込んでから気づいたために起きた手戻りです。

今回はどうなるか

直しすぎ・間違い

取り込む前に「却下」を選ぶだけで済む。CMS上で戻す作業は発生しない

漏れ

候補一覧・miChecker相当チェック・「注意」欄で、作業中に気づける

CMSに入れる前に片が付くので、やり直しが減ります。

今回やること

同じページを、3つのやり方で作業して比べる

グループごとに担当するやり方が決まっています。担当は固定で、途中で入れ替わりません。

グループ担当するやり方やること
グループ1通常移行これまでどおりの移行作業。候補レビューは使いません。
グループ2AI移行候補レビューで、移行ルール全体にもとづく候補を確認して直します。
グループ3miChecker移行候補レビューで、miCheckerが指摘する箇所だけを直します。

比べるのは かかった時間 と できあがりの品質 です。速さだけを競うものではないので、いつもどおりの丁寧さで作業してください。

作業の流れ（グループ2・3）

増えるのは、真ん中の2工程

1. CMS解析取込ツールで本文のソースを取り出す
→
2. 候補レビューに入力取り出したソースを貼り付ける
→
3. 候補を判断する1件ずつ確認して最終HTMLを得る
→
4. 取込ツールへ戻す最終HTMLを貼り付ける
→
5. CMS取込・移行これまでどおりの作業
時間は①CMS解析／②候補レビュー／③CMS取込・移行の3つに分けて記録してください。

1と4・5は、これまでのCMS作業と同じです。詳しい画面操作は 検証作業ガイドの4章 にあります。

候補レビューの画面 1

直すべき箇所が、一覧に出てくる

本文HTMLを貼り付けて「候補生成」を押すと、修正候補が並びます。

  • 画像の代替テキスト、見出し、リンク文言、表の構造などを拾います
  • もとになっているのは、これまでのマニュアルを整理した移行ルール67件
  • 同じ箇所に直し方が複数あるときは、まとめて並びます
候補が0件のこともあります。その場合も「注意」欄は必ず確認してください。

候補レビューの画面 2

4つのボタンで判断していく

ボタン意味
採用提示された修正をそのまま使う
文言を調整自分で直してから使う
却下この修正は不要と判断する
要確認自分では決めない。上長・SVへ回す

「却下」がこの検証の要です。AIが直しすぎている・間違っていると思ったら、ここで落とせます。取り込んだ後に戻す必要はありません。

判断できないものは無理に決めず「要確認」。安全側に倒してください。

候補レビューの画面 3

HTMLが読めなくても判断できる

候補ごとに「この候補で変わること」と、修正前・修正後の見た目が並びます。タグを読まなくても違いが分かります。

  • 右のプレビューで、いま見ている候補の箇所がハイライトされます
  • 表の直し方が複数あるときは、切り替えて見比べられます
  • 「（AI判定）」「（AI提案）」と付いた候補は、内容が実態に合っているか必ず人が確認してから採用します

漏れに気づくしくみ

miCheckerの指摘が、作業中に分かる

前回

取り込んだ後に検査 → 指摘が出たら戻って直す

今回

作業中の画面に「miChecker相当チェック結果」が出る

公式の判定エンジンを移植したものが動いています。どのチェックIDが本文のどこに当たっているかを、表で確認できます。

※ グループ3では、この判定が公式miCheckerと一致するかを別途確認します（この確認の時間は計測に含めません）。

もう1つの違い

「なぜそう直したか」が残る

全候補を判断し終えると、出力欄から3つを取り出せます。

  • 最終HTML — CMSに貼り付けるHTML
  • 注意 — HTMLには反映されないが、登録時に人が確認すべきこと
  • 証跡 — 誰が・いつ・どの候補を・どう判断したか（JSON / CSV）

却下した理由も残るため、「なぜAIの案を使わなかったか」を後から説明できます。前回はここが手元の記録に留まっていました。

証跡は必ず保存してください。

まとめ

変わらないこと／始める前に

変わりません

  • 取り込んだ後に、人が目視で確認しながら進める作業
  • CMSの取込作業（移行管理IDで検索 → 取り込み範囲を編集 → 登録）
  • 行政情報の中身を判断する責任は人にあること
サンプル投入は練習用のダミーデータです。本番の移行作業には使わないでください。

始める前に

  • 自分の担当するやり方を確認する（グループ1／2／3）
  • 時間を3つに分けて記録する（①解析 ②候補レビュー ③取込・移行）
  • 担当ページと移行管理IDを移行管理シートで確認する
  • 迷ったら「要確認」。速さより、いつもどおりの丁寧さ

操作の手順は 検証作業ガイド にまとめています。
